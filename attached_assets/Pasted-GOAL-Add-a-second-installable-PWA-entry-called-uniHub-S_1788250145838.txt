Add a second installable PWA entry called "uniHub Scan" whose home-screen icon opens the QR scanner directly, in one tap. The existing "uniHub" installed app (dashboard) must keep behaving exactly as it does today.

Context you can rely on (already verified from the deployed site):

The real manifest is served at /site.webmanifest and currently contains only: name, short_name, icons (/unihub-mark-192.png, /unihub-mark-512.png, /icon-512-maskable.png maskable), theme_color: "#1a1a1a", background_color: "#1a1a1a", display: "standalone".
It has no start_url, no scope, no id. That is why an installed icon lands on whatever page it was installed from (the dashboard) instead of the scanner.

STEP 2 — Changes (only after I confirm Step 1)
A. Dedicated scanner route
Make the scanner reachable at exactly /scan, as a top-level route that renders the scanner UI directly — no dashboard shell, no intermediate click.
If the scanner is currently a tab or modal, do not rewrite it. Add a thin route that mounts the same existing component with whatever props/state make it open in scanning mode.
The existing entry point (the button inside the dashboard) must keep working. /scan is an addition, not a replacement.
An unauthenticated visit to /scan must go to login and return to /scan afterwards. Reuse the existing redirect mechanism; only if none exists, use ?redirect=/scan. Do not build a new auth system.
