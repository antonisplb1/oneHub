FIX 3 — Clean re-login when the session does expire
On a 401 from any authenticated query or mutation, redirect to /auth?redirect=<current path + query> using the redirect mechanism already built in Step 2, instead of throwing.
An installed app is suspended and resumed, not reloaded. Add a visibilitychange listener that invalidates only the current-user query when the document becomes visible. Leave staleTime: Infinity on everything else.

Result: reopening after a long gap shows the login screen with Keychain-filled credentials, one tap, and back to the page they were on.

FIX 4 — Install the page the user is on

Add GET /api/manifest?start=<path>, responding with Content-Type: application/manifest+json.

Path rule — deliberately simple:

Accept the path only if it starts with /dashboard. Everything else falls back to /dashboard.
Reject anything not starting with a single /, anything containing \, //, or a scheme.
Strip the query string and hash. A merchant installing "Customers" wants the page, not the filter that happened to be applied.

The install entry points all live inside /dashboard/*, so this rule gives the user the exact URL they are on in every real case, while structurally making it impossible to pin an icon to a one-time token URL like /reset-password/:token or /spin/:token.

Manifest body:

id: the validated path. Required — with a constant id, Chrome treats every variant as the same app and silently reuses the first install.
start_url: the validated path.
name / short_name from a map, defaulting to "uniHub" / "uniHub":
path	name	short_name
/dashboard	uniHub	uniHub
/dashboard/loyalty	uniHub Loyalty	Loyalty
/dashboard/spin-wheel	uniHub Spin Wheel	Spin Wheel
/dashboard/customers	uniHub Customers	Customers
/dashboard/analytics	uniHub Analytics	Analytics
/dashboard/menu	uniHub Menu	Menu
/dashboard/shifts	uniHub Shifts	Shifts
/dashboard/team	uniHub Team	Team
/dashboard/stores	uniHub Stores	Stores
/dashboard/account	uniHub Account	Account
scope: "/", display: "standalone", and the same three icons, theme_color and background_color as site.webmanifest.

Wire it up on both paths, or it breaks on refresh:

Extend the inline <head> script in client/index.html: for a path starting with /dashboard, point the manifest link at /api/manifest?start=<path> before React boots. Check the existing /scan and /dashboard/scanner branch first and leave it exactly as it is.

FIX 5 — "Install as app" in the sidebar

Merchants will not find the browser's ⋮ menu, and iPhone has no install prompt at all. Add a sidebar entry that does it for them.

Reuse what already exists. Step 3 added an app-level beforeinstallprompt capture and an iOS instructions panel for the scanner install button. Extract both into one shared hook (e.g. useInstallApp()) and one shared instructions component, and have the scanner button and this new sidebar entry both use them. Do not create a second parallel implementation.

Sidebar entry: label "Install as app", download icon, placed with the "Support" entry in a secondary group near the bottom. Hidden entirely when already running standalone (window.navigator.standalone || matchMedia('(display-mode: standalone)').matches).

Behaviour by platform:

A captured prompt is available (Chrome/Edge, Android and desktop): call prompt(), then clear the stored event.
iOS Safari: open the instructions panel — "Tap Share → Add to Home Screen → turn on 'Open as Web App' → Add."
macOS Safari: "File → Add to Dock."
Anything else with no prompt (Firefox, Samsung Internet): "Open your browser menu and choose Install app / Add to Home screen."

The manifest race — investigate and report before choosing an implementation.

beforeinstallprompt fires after the manifest is evaluated. We now swap the manifest on client-side navigation, so a prompt captured on /dashboard may still refer to /dashboard after the user navigates to /dashboard/customers.

Store the manifest href that was active when each event fired, alongside the event.
Empirically test whether Chrome re-fires beforeinstallprompt after the manifest link changes. Report the answer.
If it re-fires: always use the latest event, done.
If it does not: when the stored href does not match the current one, set a sessionStorage flag and hard-reload the current URL — the head script then sets the correct manifest before Chrome evaluates it. After reload, the flag makes the install panel open automatically with an explicit "Install" button. Do not try to call prompt() automatically on load; Chrome requires user activation and it will fail.
