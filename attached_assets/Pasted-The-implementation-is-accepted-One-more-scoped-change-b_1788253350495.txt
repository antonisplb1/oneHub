Intended flow: log in normally → open Scanner from the side menu (/dashboard/scanner) → install the app from the browser → the icon reads "Scan" → tapping it opens the scanner directly.

Problem: the manifest swap currently only runs on /scan. Installing from /dashboard/scanner therefore installs the main "uniHub" app pointing at /, which is the original bug. Also, on a hard page load the React-mounted swap can run after Chrome has already read the manifest and fired beforeinstallprompt, so the captured prompt can install the wrong app.

Fix both. Do not change routing, the side menu, or any existing navigation.

1. Run the manifest swap on /dashboard/scanner too

Extract the existing swap logic from the /scan route into one small reusable hook (e.g. useScanManifest()), and call it from both the /scan route and the /dashboard/scanner route.

Behaviour is identical on both: set link[rel="manifest"] to /scan.webmanifest and meta[name="apple-mobile-web-app-title"] to uniHub Scan on mount; read the originals from the DOM and restore both on unmount.
Both routes point at the same scan.webmanifest, so an install from either one produces the "Scan" icon that launches /scan. That is intended.
/dashboard/scanner keeps its dashboard chrome and its manual Start Camera button. Only the manifest tags change.
2. Add an inline script in client/index.html <head>

This must run before React boots, so a hard load or refresh on either scanner URL has the right manifest before Chrome evaluates installability.

Place it immediately after the existing <link rel="manifest"> and <meta name="apple-mobile-web-app-title"> tags:

html
<script>
  (function () {
    var p = location.pathname;
    if (p === '/scan' || p === '/dashboard/scanner') {
      var m = document.querySelector('link[rel="manifest"]');
      if (m) m.setAttribute('href', '/scan.webmanifest');
      var t = document.querySelector('meta[name="apple-mobile-web-app-title"]');
      if (t) t.setAttribute('content', 'uniHub Scan');
    }
  })();
</script>

No framework, no dependency, no build step. Keep the hook from point 1 as well — the script covers hard loads, the hook covers client-side navigation.

3. Add an "Install scanner app" button on the scanner page

Visible on both /scan and /dashboard/scanner. Merchants will not find the browser's ⋮ menu on their own.

Behaviour:

Listen for beforeinstallprompt at the app level, preventDefault() it, and always store the most recent event, overwriting any earlier one. Do not store only the first.

Style it with existing components/classes. Do not introduce new design patterns or a new dependency.
